# Content provenance and independent authorship

Publisher: **the aivideoweb.com team**. Editorial date: **2026-10-21**.

## How this collection was made

The collection starts from common production needs: a shop image, a launch poster, a classroom diagram, a consistent storyboard or a narrowly scoped edit. Each entry has a newly written brief, fictional subjects where appropriate, explicit constraints and task-specific review criteria.

No third-party prompt body, screenshot, preview image, contributor profile or developer identity has been imported into this repository. The collection does not claim that common concepts such as product photography or storyboards are exclusive inventions.

English and Chinese versions share an ID. The original catalog contains 48 scenarios, not 96 independent concepts. Preview assets were newly generated from this repository's English prompts; the cover has its own original prompt recorded in the manifest.

## Inputs and references

- [Google's model documentation](https://ai.google.dev/gemini-api/docs/models/gemini-nano-banana-2.1) is the factual source for model naming and capability context. See the dated model guide.
- [Awesome SEO Writing Skill](https://github.com/flaqai/Awesome_SEO_Writing_Skill) was consulted for its general editorial approach: clear intent, checked claims and portable deliverables. Its implementation and text were not copied into this project.
- Broad image-making categories were treated as common creative tasks. No third-party gallery entry was used as a template for individual wording or composition.

## Assets are not model benchmarks

`assets/generation-manifest.json` records each asset's original prompt, generator, dimensions, checksum and limitations. The built-in imagegen tool did not expose a specific model ID. We therefore record the tool name and do not infer a hidden model.

All catalog entries target Nano Banana 2.1, but remain `not_tested` on that target. A new image is evidence that an image was generated, not evidence that another model produced it.

## Future contributions

Keep a source record. If you incorporate licensed third-party material, follow its license and retain required attribution. Rephrasing a copied prompt or removing a creator's name is not an acceptable provenance workflow. Prefer independently designed briefs and original assets.

A claim of originality does not certify clearance or guarantee that no similar work exists. Report a specific conflict through a repository issue, identifying the entry and evidence. Maintainers should inspect it and revise or remove material when appropriate.

## Public X case expansion — 2026-10-21

The library now includes 24 newly written adaptations informed by publicly readable X case themes. The original 48-entry foundation is retained. Sources were discovered through Google in the browser and read on public X article/post pages without signing in. The first web-search connector attempts did not surface these sources; browser discovery did.

See `data/sources.json` and [the readable source register](x-case-sources.md). Each new recipe links a specific inspected section and distinguishes the publisher's model claim from this project's still-pending reproduction. Tutorial proposals, reported tests, a quoted post and a discovery thread are explicitly different evidence levels. The discovery thread is not counted again as a demonstrated recipe.

Prompts were redesigned with new subjects, layout choices, text and review checks. They are adaptations rather than verbatim source prompts. When the original prompt was not visible, the entry says so; reconstructed production briefs are not labeled as recovered prompts. Source author names and links are retained for traceability. No source image has been downloaded or republished and no external speed, price or ranking conclusion is adopted.
